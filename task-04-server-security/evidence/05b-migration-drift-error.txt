##### Reading of this (written by Claude)
  `migrate status` said "Database schema is up to date!" even though someone had added a column by hand. It only compares the list of migration files with the list recorded in the database, not the tables themselves.
  `migrate dev` does compare the real schema with what the migrations would build, and found the extra column. It refused to continue and offered only `prisma migrate reset`, which drops the data. It created no migration and changed nothing (still 4 recorded).
  So the lesson for production is: never change the database by hand. If someone does, `migrate status` will not warn you, and the next `migrate dev` wants to wipe the database. The safe route is to put the change in a migration file, or to run `prisma migrate diff` and write the matching migration.
