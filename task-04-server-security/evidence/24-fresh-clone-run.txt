##### Reading of this (written by Claude)
  What worked from a fresh clone with only DATABASE_URL set: install, prisma generate, migrate deploy, seed, build, the pages, registration (201), the verify route (generic 400), and the paused booking (503). No step needed anything that was not in the README, up to that point.
  What failed: the worker. The registration queued a job, and the worker could not make a code because VERIFICATION_SECRET was not set. The job went to "retry" with the clear message "VERIFICATION_SECRET must be set in .env and be at least 32 characters". No code was stored and no email was sent. The README did not mention the secret, the SMTP settings or the worker. That was a gap in the README, not in the code.
  Fix: the root README now lists VERIFICATION_SECRET and the SMTP_* names, says how to make the secret, and says to start `npm run worker` in a second terminal. The old name SMTP_PASS in the README was also wrong (the code reads SMTP_PASSWORD) and is corrected.
  Not tested: a run with the new README by a person, and sending a real email from the clone (that needs real Gmail credentials, which a clone does not have).
