# - The FIRST request is slow in both runs (477 ms before, 436 ms after). That is a cold start: the route is loaded and the first database connection is opened. It is the same with and without validation, so validation is not the cause. This is a guess from the pattern; I did not measure the two parts separately.
# - The other nine requests vary a lot from run to run on this laptop (8 to 98 ms before; 10 to 82 ms after; a separate warm run had 8 to 37 ms), with no code change between them. Ten requests cannot tell a few microseconds from that noise.
# - The direct measurement is the benchmark above: about 2.6 microseconds to validate a good request and 5.5 to reject a bad one. The schema is built once when the server loads, not on each request.
# - A rejected request is quick (about 4 to 25 ms), because it stops before the database is touched.
